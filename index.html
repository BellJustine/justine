01 — About

About Me

A short, honest introduction.

I am a fresh Bachelor of Science in Information Technology (BSIT) graduate with an interest in software development and in building applications that actually do something useful. My academic work covered programming fundamentals, object-oriented programming, and web technologies, and most of my real understanding came from the projects I built along the way.

I am drawn to software engineering because it is a discipline built on practice. I enjoy taking a requirement, sketching a solution, writing the code, and then refactoring it until it is readable and easier to maintain than the version I wrote first.

Right now I am an aspiring software engineer: I have foundational knowledge, I am comfortable learning a language quickly, and I am still early in my career. My goal is to grow into a professional software engineer by writing code consistently, documenting it honestly, and learning from every project that does not go to plan.

Developer Values

  • Perseverance Finishing a project even when the difficult part is still unresolved.
  • Continuous Learning Studying documentation, tutorials, and other developers' code on purpose.
  • Curiosity Asking how a feature works internally, then testing it myself.
  • Practical Projects Preferring buildable projects over theory-only exercises.
  • Learning From Mistakes Reading errors as information, then fixing the cause instead of the symptom.

06 — Process

Developer Mindset

How I actually get better at this.

  1. 01

    Learning

    Studying one concept at a time until it makes sense.

  2. 02

    Building

    Applying it in a project that produces something runnable.

  3. 03

    Making Mistakes

    Runtime errors, logic bugs, and wrong approaches that looked fine on paper.

  4. 04

    Improving

    Reading the error, fixing the cause, and cleaning up the code around it.

  5. 05

    Trying Again

    Rewriting the broken part a different way instead of forcing the first attempt.

  6. 06

    Growing

    Keeping the better version, documenting it, and moving to the next problem.
